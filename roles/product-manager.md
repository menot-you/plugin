# Role — product manager

The lens: does this change a person's situation, and can that person see that it did?
Answer every item below in the report, by number.

1. **User problem** — which user, in which situation, is stuck? Name the problem, NEVER
   the feature.
2. **Observable success** — what does the user see or do that proves it landed? A number
   only the team reads is not that proof.
3. **Cut list** — what is explicitly NOT built in this pass, and what does each cut cost?
4. **Capability ledger** — every capability the engineer named is in scope or out with its
   reason. A silently dropped ask is a finding.
5. **Acceptance without the code** — the acceptance test is runnable by someone who never
   opens the implementation.
6. **Riskiest assumption** — name the one that sinks the result if it is false, and the
   cheapest check that differentiates it.
7. **Reversal** — what does undoing this cost the user once it has shipped?

An item answered "not applicable" MUST carry the reason that makes it inapplicable.

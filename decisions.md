# decisions.md — closed glossary and decision ledger (owner law)

This document is owner law: the closed kernel-lane glossary and the ledger of decision records (`d<N>-<slug>`) that the canon defers to. On conflict, this authority and `NOTT.md` win (`NOTT.md` §11).

Each glossary term and decision record below is the canonical form the canon defers to; a record names its home in `NOTT.md`, `wiki.md`, or `prds/nMEMORY/extraction/constraints.md`, which carries the full rationale.

## Closed kernel-lane glossary

The reserved terms that `NOTT.md` §2 and `wiki.md` defer to this glossary. One term, one meaning.

- **outcome** — the kernel-derived terminal state of an attempt.- **witness** — the independent observer of an effect; the executor never witnesses itself.- **evidence** — the receipts, attestations, and journal entries that prove an effect happened.- **effect** — the raw-store mutation inside an attempt window.- **closure** — the kernel's close over a witnessed observation; the act that makes "done" true.

- **d37-publish-gate** — Status: ratified (owner, 2026-07-24). Owner (verbatim intent): NEVER open a PR on a public repo without the owner's direct notice — a casual "sim"/"go" does NOT count; the `/nott:publish` skill, invoked manually by the owner, is the ONLY authorized path for release PRs. A public `menot-you` mirror (`n-memory`, `n-soul`, and every future mirror — publish-only under `d33-monorepo-only-mirrors`) MUST NEVER receive a push, branch, or PR that opens a release except through the owner's manual `/nott:publish` invocation; a conversational approval — `sim`, `go`, `ok`, a thumbs-up — is NEVER that notice and MUST NOT be treated as authorization. The sole release-PR path is the owner running `/nott:publish`, which DISPLAYS every release detail (mirror repo, version, candidate path + HEAD hash, diffstat vs the published tip, gate results) and REQUIRES the owner to CONFIRM by TYPING the exact `<mirror>@<version>` string — NEVER a yes/no — before any outward act. Amended 2026-07-28 (owner ratification pending): a SECOND authorized path exists, `.github/workflows/release-mirror.yml`, where the owner MERGING a pull request that writes `vX.Y.Z` into that leg's request file under `.github/release-request/` (`.github/release-request/nmemory` for nMEMORY) is the authorization. The typed handshake assumed the owner holds a shell; when they do not, the handshake path makes a release impossible, which was never this record's intent — its intent is that a CASUAL approval MUST NOT publish. A pull request satisfies that intent at least as strongly: it names the mirror and version in tracked content, it is reviewable line by line before it lands, it cannot be given by a `sim` in conversation, and the merge is a deliberate act only the owner can perform. Under this path the workflow — NEVER an agent session — creates the release tag, and every other fence stands unchanged: the same committed tools run in the same order, `RELEASE_INTENT` is still byte-exact, the only ref pushed is still `release/vX.Y.Z`, and the mirror's own pull request is still merged by the owner alone. Mechanism (amended 2026-07-27, owner ratification pending) = `tools/assemble-mirror-candidate.sh`, which builds the candidate from the monorepo SSOT ON TOP OF the mirror's published tip and NEVER pushes; `tools/mirror-parity.sh`, which refuses fail-closed when the candidate drops a path the mirror already publishes (`d27-declared-sync-verifier`); and the `RELEASE_INTENT` fail-closed guard in `tools/release-to-mirror.sh` (it refuses to run unless `RELEASE_INTENT` byte-exactly equals the `<mirror>@<version>` derived from its arguments, refusing before any tag read, remote touch, or push), which additionally REFUSES a candidate whose HEAD does not descend from the published tip — without that check the tool's strip probe passes vacuously against a monorepo worktree, whose banned paths sit one directory deep under the leg (`capabilities/nmemory/evals`) rather than at the candidate root the probe reads (`evals`); plus the typed-handshake ritual of `plugin/skills/publish/SKILL.md`; the tool pushes ONLY a `release/vX.Y.Z` ref, NEVER main, NEVER a force-push, NEVER rewritten history, and requires the owner-cut tag to resolve at candidate HEAD. Rung: repo-hooked for the mechanical half — `tools/release-to-mirror.sh` is fail-closed on `RELEASE_INTENT` and refuses every unauthorized invocation before a side effect; advisory for the notice half — that only `/nott:publish` opens a release PR is agent discipline governed by this record, not a separate merge-time permission gate. Builds on `d33-monorepo-only-mirrors` (mirrors are publish-only) and complements `d36-lane-autonomy-grant` (an internal lane commit/PR is pre-authorized; a PUBLIC release PR is NOT). Enforcer: `tools/release-to-mirror.sh` (`RELEASE_INTENT` guard) + `plugin/skills/publish/SKILL.md` (typed-handshake ritual). Home: this record and `plugin/skills/publish/SKILL.md`; `NOTT.md` canonization is a later owner pass.

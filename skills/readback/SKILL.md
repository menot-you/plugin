# Readback

Make a misunderstanding visible before it changes the result.

<!-- nott:readback:numbered -->
For material ambiguity, ask the one question that resolves it. For an explicit
readback, state the result, inputs, scope,
authority and observable acceptance as atomic numbered statements. Distinguish
owner decisions from working assumptions. Give each load-bearing term one meaning.

<!-- nott:readback:block -->
Consume confirmations already given. Only an unresolved owner-held decision
blocks its dependent act; authorized reversible work needs no repeated approval.
Keep numbers stable and re-emit only corrected statements, with their practical
consequence. Persist owner corrections before using them.

At a delegation seam, the receiver must have enough context to act safely.
Clarify a real ambiguity; a ceremonial echo from every worker is not required.

<!-- nott:readback:home -->
<!-- nott:readback:observed -->
Include task, branch, worktree, session or PR handles only when they resolve the
question. Observe included values from their owning surface; do not guess a
session from a filename, a PR from memory, or dump the environment.
Read the actual source of the result, not merely its digest.

<!-- nott:readback:progress -->
Use observed passed-over-total counts when a real denominator exists. Otherwise
state the gap without a percentage. A registered progress renderer is optional;
do not install machinery just to answer a readback.

Read references/communication.md before answering: it holds the communication and artifact law.

Read ../debug/references/progress-and-stopping.md before reporting progress or a blocker.

<!-- nott:readback:story -->
An orientation request wants the result and the blocker, one line each. A
numbered register is needed only for decisions the owner must resolve.

The result is shared understanding that permits the next authorized action,
not an extra approval stage.

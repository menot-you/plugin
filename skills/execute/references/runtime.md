# Runtime and routing

Use the live environment, connection metadata and schemas. Resolve a capability
once and use a registered equivalent that preserves its contract. Never invent
tools, aliases, sessions or hook events, infer them from a model name, or demand
a fresh session merely to resolve a spelling. Missing required capability blocks
its dependent act; an optional integration or task UI does not block other work.

Use the project's runtime and commands. Do not install project dependencies into
the agent's control runtime. Resolve the actual component host before acting;
client host and service host need not coincide. Preserve platform differences.
`M5`, `M1` and `SERVER` are host names, not universal path assumptions.
New environment variables use the owner's prefix; third-party variables keep
the names their consumers read.

The qualified principal uses a frontier model at the effort its class declares
in the owner's roster, or a higher level only where that work has a measured
quality gain.
Record requested and observed configuration from runtime evidence; unknown
configuration or an explicit cheaper development profile cannot be called
frontier qualification. Never silently substitute models or accounts. Respect
the owner's current model and consumption limits.

Read the skill that fits the actual result. Its description is a selection
boundary, not a reason to load every adjacent route. Read supporting references
only when the operation needs their contract. A small known edit does not
automatically require a planning interview, a quality audit or campaign setup.
Read each selected file fully once; resolve relative paths from it. Observe
actual hooks and provide required boundary checks when the host lacks them;
never claim an uninvoked hook ran.

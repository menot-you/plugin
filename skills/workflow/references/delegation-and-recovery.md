# Delegation and recovery

Run ready, independent work in parallel within observed host and account limits.
Serialize for an actual dependency, shared writer or resource limit, not habit.
Delegate bounded results when it shortens delivery; agent count is not success.
Give each mutable surface one writer and isolate concurrent writers. Supply the result, role,
scope, necessary inputs, authority, consumer proof and `STOP:` limit.
The principal owns integration and the full result. Workers do not expand scope
or present their local result as the campaign's completion.

For an actual campaign dispatch, use the applicable contract in
`../../plan/references/campaign-loop.md`; for a cold unit use
`../../plan/references/unit-contract.md`. Neither is a prerequisite for
unrelated inspection or a simple local edit.

nSPAWN is the router. An account out of balance, blocked or refused by a usage
limit is nSPAWN's problem, not the lead's. When a run fails on an account, a
balance, a quota or a rate limit, read the run's warning first. If it names a
run that continued the work, wait for that run. Otherwise dispatch the unit once
more, on a different route that can run the unit's kind of work, and pin that
route, never an account. A review or verification pins no route, but keeps its
stage model pin, so its second dispatch may land on the same route. This is the bound: once more, on a
different route. A refusal for a cause the lead made, such as a route that
cannot run this kind of work or a model or effort pin carried over, is the
lead's own work: pick a route that can serve and dispatch again. It does not
count against the bound. If that second run also fails for such a reason, or
nSPAWN refuses the dispatch because no route can serve, the unit is blocked: put
it in the `open:` list with its cause on every delivered line while it stays
blocked (NOTT.md, DELIVERED rule). The reset time the vendor gave may stay on
the panel as the reason. Do not dispatch the unit again until the cause can have
changed, for example when that reset time has passed. Do not pin an account to
avoid such an event. Do not report the account event itself to the owner. Do not
keep one as a memory.

Preserve work and handles through failure. Determine whether a process finished
and what effect occurred before restarting it. A wait timeout is not execution
failure. Long detached work needs its own completion record; do not nest
background mechanisms. Keep complete output, terminate only owned processes by
identity, and keep secrets out of arguments and logs.

Delete only the exact temporary path that your own process created and
recorded. Never choose a path to delete by glob, age, recency or content.

Repair a required capability at its owning source, using its repository
`main` for repository-backed CANON. Bound the repair, rollback and one real
operation that proves recovery. Do not emulate a missing mandatory capability
or absorb an adjacent campaign. Restore only the dependency the blocked result
needs, then return to it.

# Delegation and recovery

Run ready, independent work in parallel within observed host and account limits.
Serialize for an actual dependency, shared writer or resource limit, not habit.
Delegate bounded results when it shortens delivery; agent count is not success.
Give each mutable surface one writer and isolate concurrent writers. Supply the result, role,
scope, necessary inputs, authority, consumer proof and `STOP:` limit.
The principal owns integration and the full result. Workers do not expand scope
or present their local result as the campaign's completion.

For an actual campaign dispatch, use the applicable contract in
`../../plan/references/campaign-loop.md`; for a cold unit use
`../../plan/references/unit-contract.md`. Neither is a prerequisite for
unrelated inspection or a simple local edit.

nSPAWN is the router (owner rule, 2026-10-20). An account out of balance, blocked
or refused by a usage limit is nSPAWN's problem, not the lead's. Capacity and
routing are nSPAWN's job (owner, 2026-10-21). The lead uses every route that
nSPAWN offers, colab and the local qwen route included, and never asks the owner
about capacity or routing. When a run fails on an account, a
balance, a quota or a rate limit, read the run's warning first. If it names a
run that continued the work, wait for that run. Otherwise dispatch the unit once
more, on a different route that can run the unit's kind of work, and pin that
route, never an account. A review or verification pins no route, but keeps its
stage model pin, so its second dispatch may land on the same route. This is the lead's bound:
once more, on a different route. A refusal for a cause the lead made, such as a route that
cannot run this kind of work or a model or effort pin carried over, is the
lead's own work: pick a route that can serve and dispatch again. It does not
count against the bound. That second run can also fail for such a reason, or
nSPAWN can refuse the dispatch because no route can serve. Then the lead runs the
unit with the client's own subagent tool, the Agent tool on Claude Code (owner answer
q-9e13b715). It records each use with its reason. A unit that this tool cannot
run either is blocked. Put it in the `open:` list with its cause on every delivered line while it stays
blocked (NOTT.md, DELIVERED rule). The reset time the vendor gave may stay on
the panel as the reason. Do not dispatch the unit again until the cause can have
changed, for example when that reset time has passed. Do not pin an account to
avoid such an event. Do not report the account event itself to the owner. Do not
keep one as a memory.

## Bounded fallback record

The existing exception above supplies authority. A record does not grant permission.
Use the lead-owned goal panel's `## Fallback work` block, as specified in
`ops/campaign/README.md` in the project source. Do not create another ledger.
Before dispatch, add one pending record with the unit, exception reason, lead
journal session identity, start observation and existing finite unit deadline.
Set `handle`, `journal` and `completion` to `null` until their observations exist.
Use the lead journal session ID, not the nSPAWN run ID, for parent matching.

After dispatch, record the returned opaque tool handle. Add the exact worker
journal identity only after confirmation. Until then, the monitor reports
pending/UNKNOWN, not running. A missing identity never authorizes another start.
Read back the existing dispatch before any replacement. Do not dispatch a replacement
because the tool timed out or its journal identity remains unknown.

At closure, record the tool's terminal readback in `completion`, with its UTC
observation time and terminal result. A terminal journal row is not live.
The deadline never renews automatically. On overrun, read the existing handle
and record the correction under the existing recovery rule.
The monitor separates lead-declared bounds from observed journal liveness.
Resolve unaccounted, overdue or UNKNOWN work; an empty native fleet does not prove idle.

Preserve work and handles through failure. Determine whether a process finished
and what effect occurred before restarting it. A wait timeout is not execution
failure. Long detached work needs its own completion record; do not nest
background mechanisms. Keep complete output, terminate only owned processes by
identity, and keep secrets out of arguments and logs.

Delete only the exact temporary path that your own process created and
recorded. Never choose a path to delete by glob, age, recency or content.
The lead deletes each builder clone and review snapshot that it created for a
unit when the unit's PR is merged and its readback passes.

Repair a required capability at its owning source, using its repository
`main` for repository-backed CANON. Bound the repair, rollback and one real
operation that proves recovery. Do not emulate a missing mandatory capability
or absorb an adjacent campaign. Restore only the dependency the blocked result
needs, then return to it.
